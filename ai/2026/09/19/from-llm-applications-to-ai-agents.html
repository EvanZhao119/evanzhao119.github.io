From LLM Applications to AI Agents

RAG gives an LLM access to relevant external knowledge, while tools allow it to interact with other systems. An AI application starts to become agent-like when the model can use the result of one step to decide what to do next.

Instead of following only a single question-and-answer step, an agent-style system can work through a task over multiple steps. At each stage, the LLM evaluates the previous result and determines the next action.

What the Article Covers

  • How agent-style systems differ from basic chatbots
  • Why some user requests require multiple steps
  • How an LLM can choose the next action based on an earlier result
  • The relationship between goals, reasoning, tools, actions, and observations
  • How prompts, RAG, tools, and the LLM work together
  • Why modern LLM engineering involves building a complete system around the model

A basic agent process can be represented like this:

Start with a Goal
        ↓
Reason About What to Do
        ↓
Choose a Tool
        ↓
Take an Action
        ↓
Observe the Result
        ↓
Reason Again
        ↓
Continue Until the Task Is Complete

The important distinction is that an agent’s workflow does not always need to be completely defined in advance. The model can use the information it receives at each step to determine what should happen next.

In the larger system, the prompt describes what is needed, RAG supplies relevant knowledge, tools provide capabilities, the LLM reasons about the available information, and agent-style orchestration repeats the process until the task is complete.
